## 画面と操作

### メイン画面
| 操作 | 動作 |
|---|---|
| セルをタップ | +1（水色フラッシュ）。振動する（設定なしで常に ON。2026-10）。カウントロックした項目はタップ無効（表示だけ。暗くして🔒。入力モードでも変えられない。まとめて加算・ショートカット送信では入れられる） |
| セルを長押し（300ms で赤） | −1。g/b/r は打ち始め値未満にならない |
| （押した後） | ボタンの真下（下の隙間）に実際の増減を小さく出し、4.1 秒（1回転分。2026-10-04 に 1.5 秒から変更）で消す（+ は水色、− は赤、±0 は白）。消える前に同じボタンを操作したら合計を出し直して時間をリセット（2回タップで +2、タップ→長押しで ±0。G数は +50 ずつ、下限で変わらなければ ±0）。指でセルが隠れる・横置きで振動が分からない時のため（2026-10）。メイン画面の外の層に出すので描き直しでも消えない。画面の向きが変わったら消す。BIG/REG の +1 はすぐテンキーが開いて表示がその下に隠れるが、テンキーが開くこと自体が合図なので手前には出さない（キーに重なって見づらくなるため） |
| BIG/REG を +1 | その時点で当選記録を作成し、テンキーパネルを表示（回転数を入力） |
| BIG/REG を −1 | 同種の最新記録を削除（確認なし）。最新の当選を消したときは、G数・ハマりを**押す前のハマりに戻す**（押した後にタップで足した分は残す） |
| ＜打ち始め＞のセル | カウントロックを外したときだけ＜現在＞と同じ操作（タップ +1・長押し −1。G はタップ +50・長押し −50。入力モードは入力）。変えると＜現在＞も同じだけずれる（打ち始めからの差分＝自分が打った分は変わらない）。0 未満にはならない。BIG/REG を変えても当選記録は作らない・消さない。ロック（初期値）なら表示だけ |
| 機種名を長押し（550ms） | まとめて加算パネル（2026-09 に「タップ」から変更） |
| 機種名をタップ | 詳細記録 ON のとき画面1・画面2 の切替（機種名の左右の ○● で表示中の画面。左＝画面1、右＝画面2）。詳細記録 OFF の間は何もしない |
| 左上 🔍 | 大当たり分布モーダル |
| 右上 ⚙️ | 設定モーダル |

振動: iPhone Safari は `navigator.vibrate` 非対応なので、iOS 18 以降の「スイッチ型チェックボックスを切り替えると触覚フィードバックが出る」挙動を利用している（非公式。iOS 側の「システムの触覚」が ON である必要あり）。
- メイン画面の各セル（カウンター・ランプ）に透明な `<label class="haptic-tap">`（中に非表示の `<input type="checkbox" switch>`）をかぶせ、**指のタップそのもの**でスイッチを切り替える。プログラムからの `label.click()` は WebKit の修正（[fc1ef83](https://github.com/WebKit/WebKit/commit/fc1ef83eae10068fe468587d959e868041ddfe03)）で振動しなくなったため使わない
- そのためタッチではセルへ明示的にポインタキャプチャしない（キャプチャすると click の宛先がセルになりスイッチが切り替わらない）。マウスのみキャプチャ
- iOS はタップが click になった時だけ振動する。長押し（−1）やタップ直後に画面を描き直す操作（BIG/REG の −1 など）では振動しないことがある
- **振動したのに数えない、を無くす**: 加算は pointerup で行うが、iOS が pointerup の代わりに pointercancel を送ったり pointerup が届かなかったりしても、振動用ラベルの click が来たら（＝振動したら）その時点で数える（click 補完）。1回の押下につき1回だけ数える（ラベルとスイッチの click が2回来ても1回）。長押し（300ms 以上）の判定は click 補完では押していた時間で行う。指を 50px 以上動かしてキャンセルした押下は数えない
- **セルで押し始めていない click は打ち消す**: 「＜ベル＞」などの見出しの文字（セルの外）を押すと、iOS Safari のタップ位置補正で近くのセルの振動用ラベルに click だけが届き、振動するのに数えない（pointerdown は見出しに行くので記録にも残らない）。**一番最近の押し始めがそのセル**で、押し始めて2秒以内の click だけを扱い（前の押下で click が来なかった後に見出しを押した場合も打ち消せるよう、画面全体で押し始めた場所を覚える）、それ以外は `preventDefault` してスイッチを切り替えない（振動させない）。タップの記録には「打ち消し(枠外のclick)」と残す。ラベルが中のスイッチへ送る2回目の click は触らない（打ち消すと本物のタップでも振動しなくなる）
- click 補完で数えた押下も、次の押下の開始時も、長押しタイマーと色を必ず止める（前の押下のタイマーが次の短いタップを −1 にしないため）
- 管理画面（設定画面の左上の🔑）に「操作ログ」（調査用・直近20件、新しい順。2026-10 に設定画面の一番下から移動。見出しの「（調査用・直近20件）」は 2026-10-04 に削除）: 時刻・セル・届いたイベント（down / up / cancel / move / click）・押していた時間（up/cancel が来なければ click までの時間）・結果（**実際の増減**: +1 / −1 / +50（G数）/ 変化なし(長押し・下限) / (click補完) / 数えず）。数え漏れが起きたらここのスクリーンショットで原因を調べる（メモリ上だけで保存しない）
- `navigator.vibrate` がある端末（Android 等）はそちらで振動
- **セル以外の押せるもの**（2026-10-04）: 各画面のアイコン（🔍 ⚙️ 🔑 📋 ✕）、機種名、大当たり分布のタイトル、設定のボタン、各画面のボタン・タブ・テンキー・契機/告知、当選履歴の行、実戦履歴のフィルタ・履歴、カウントロックのボタン、設定推測のタップできる行にも同じ振動用ラベルをかぶせる（`addHaptics`。対象は `HAPTIC_TARGETS`。描き直しで出てくる要素と、中身を書き換えた要素〔データ保存のボタンの「保存中...」など〕にも DOM の変化を見張って付け直す。ラベルをかぶせるため対象は position: relative〔同じセレクタの CSS で指定〕）。押せないもの（見えない✕・設定推測のタイトル・押しても何も起きない行）には付けない
  - 押した時の処理は要素の onclick などのまま（ラベルの click がそのまま伝わる）。ラベルが中のスイッチへ送る2回目の click はラベルで止める（止めないと処理が2回動く。ロックの切替なら元に戻ってしまう）
  - 機種名は中身（`#disp-machine-name`）だけ書き換え、ラベルを描き直しで消さない（押している最中に消すと振動しない）
  - 押した瞬間に自分を描き直すボタン（全体/BIG/REG・ロックの切替など）は、ラベルが外れた後にスイッチが切り替わる。実機で振動するかは要確認

レイアウト: 縦画面は1カラム、横画面は左右2カラム（右カラム=ランプ・レトロ）。スクロールなしで1画面に収める。

説明文（「G数をタップすると修正できます」のような案内・注記）は出さない（2026-10-04 ユーザー指定。当選履歴・確率表・テンキー・まとめて加算・管理画面の案内を削除）。

### レトロ条件達成の自動加算
タップで記録した当選（`hits`）から自動で数え、増減分だけ `cur.retro_d` に反映する（`retroAutoCount` / `syncRetroFromHits`）。常に自動（設定なし）。
- **連チャン** = 前の当たりから **100G 以内**（100G ちょうどを含む）。REG 始まりでも連チャンに数える
- 連チャン中の **BIG の数が 2〜4** の間の当たり（その BIG 自身と、その後の BIG・REG）が対象。BIG5連目以降は対象外
  - 例: BIG → REG → REG → BIG(対象) → REG(対象) = 2 / REG → BIG → BIG(対象) = 1 / BIG が6連 = 3
- 最初の記録（その前の当たりが分からない）と G数未入力の当たりは連チャンの始まり扱い（対象外）
- **告知がフリーズの当選自身は対象外**（2026-09-30。BGM が上書きされて鳴ったか分からない）。ただし連チャン中の BIG の数には数える（後ろの当たりは対象になりうる）。後告知は自動では外さない
  - 例: BIG → BIG(フリーズ) → BIG = 1（3つ目は BIG3連目で対象）
  - テンキー画面でフリーズにした・外した時点で数え直す。この機能より前に手で −1 していた当選に後からフリーズを付けたら、手で +1 して戻す（運用）
- 反映は当選の G数を入力した時点。G数の修正・当選の取り消しにも追従する（対象だった当選を消せば −1。0 未満にはしない）
  - 取り消しは「その当選が無かった場合の流れ」で数え直すので、−1 以外になることがある。例: BIG(300) → BIG(60) → REG(60) で2つ目の BIG を消すと、REG は最初の BIG から120G後になり連チャンではないので 2 → 0。BIG5連目が4連目に繰り上がって増えることもある
  - テンキーで入力中は、開いた時点の値を基準に最終的な差だけを反映する（「120」と打つ途中の「1」「12」で一時的に連チャン扱いになっても、ずれを残さない）
- **手で直した分は残す**（後告知・フリーズ・目押しミスはレトロ達成のセルで手動 ±1）。まとめて加算・入力モードで BIG を増やしても自動では増えない
- 自動では判定できないケース（ユーザー情報。手動の加減算が必須）:
  - フリーズで当たった BIG は連チャン中でもレトロ対象外（上書きされて不明）→ 当選の告知を「フリーズ」にすれば自動で外れる
  - 内部的には100G以内の当たりでも、実G数（データカウンター）では100Gを超えて見えることがあり、それも連チャン・レトロ対象になる → 自動では数えないので手で +1
  - 手で +1 した当選の G数を後から100G以内に直すと、自動でも +1 されて二重になる（直したらレトロ達成も確認する）
- 自動加算の導入前の保存データは、読み込み時の当選履歴から数えた値を基準にする（読み込んだだけでは変えない）

### テンキーパネル（大当たり回転数）
- 配置（BIG/REG 加算時）: 下端は画面の一番下まで伸ばし、キーを縦に大きくする（枠が画面端に接しないよう、下端は 8px（safe-area がある端末はその分）、横画面の上端は機種名バーから 4px 空ける）
  - 縦画面: 上端をスイカの個数（数字）の位置に合わせる（スイカの項目名は見える）
  - 横画面: 右カラムの幅いっぱい（ベルの枠と同じ幅）に被せ、上端は機種名バーの直下
- 大当たり分布の当選履歴から編集する時は画面中央（高さは中身なり）
- 配列 `7 8 9 / 4 5 6 / 1 2 3 / ⌫ 0 OK`、キー左・表示右
- 入力は **4桁（9999G）まで**。G数表示は「4桁＋G」がちょうど収まる幅（数字の左右の余白は同じ）で、残りの幅はすべてテンキー
- 入力のたびに記録へ即反映。✕・外側タップ・OK のどれで閉じても値は残る
- 未入力で閉じると `g: null`（未入力）の記録になる
- **当選の契機・告知**のボタン（詳細記録 OFF でも記録。見た目は UI 調整で詰める）。押すとその記録にすぐ反映
  - 契機（1つ）: 単独(先)・単独(後)・チェリー・スイカ・リプレイ・ベル。初期値 単独(先)。小役重複は後告知に該当
  - 告知（1つ）: ノーマル点滅・プレミア点滅・フリーズ。初期値 ノーマル点滅（点滅とフリーズは同時に起きない）
  - 付随（複数可）: 特殊テンパイ音・バイブ・バウンドストップ（ボタンは「バウンド」と略記。2026-10-05 に追加）。アメイジングチャンスは 2026-10-05 にボタンを無くした（ほぼ出ないため。今までの記録に付いている分は消さず、備考・プレミア・シートの文字列に残す）
  - テンキー画面には回数や割合を出さない（割合は当選履歴の円グラフ。2026-10-04）。この機能より前の記録は初期値として扱う
  - 置き場所（テンキーのキーは元の大きさのまま）: **縦画面はキーの下**（BIG/REG 加算時は今までのパネルの上端＝スイカの個数の位置から、欄の高さ＋余白の分だけパネル全体を上へ伸ばす。テンキーは同じ大きさのまま、その分上へずれる）、**横画面はキーの右**（幅250px。BIG/REG 加算時はテンキーを右カラムの幅のまま、パネルを左へ伸ばす）。当選履歴からの編集（中央表示）も同じく縦は下・横は右。万一画面に入りきらない時だけパネルの中をスクロール

### ショートカットからのベル送信（URL）
`index.html?bell=135&t=20260927153012` で開くと、選択中の機種のベルを `bell` の値で**上書き**する（加算ではない）。iOS ショートカットで数えた `count.txt` の合計を送る用途。設定手順は `docs/SHORTCUTS.md`。
- 保存できたら `history.replaceState` で URL からクエリを消す（再読込で上書きし直さない）。保存に失敗したら URL を残す（再読込で送り直せる）
- `t`（送信日時 yyyyMMddHHmmss の14桁）が前回適用分（`data.lastBellSyncT`）以下なら無視する。`t` が無い・14桁でなければ「日時なし」として常に上書き（保存済みの値が壊れていても以後の送信を止めない）
- `bell` は0以上の整数（文字列全体が数字）だけ受け付ける。`135abc` `37.9` などは無視
- 起動時は「使用権を取る → 保存データを読み直す → 画面表示 → 確認ダイアログ → 送信を適用」の順（`startup()`）。スクリプト読込〜起動の間に別タブが保存した分を失わないため
- 上書き前に、画面を表示してから確認ダイアログ「（機種名）ベルを 120 → 135 に上書きしますか？」を出す。キャンセルなら上書きせず URL だけ消す。今のベルと同じ値なら聞かない
- 上書きしたらベルのセルを一瞬光らせる（バナーは出さない）
- アプリ内のベルのタップはそのまま使えるが、次の送信で上書きされる

### 複数タブ対策
送信のたびに Safari で新しいタブが開くため、最後に開いた（読み込んだ）タブだけを「使えるタブ」にする（localStorage `hana_active_tab` にタブIDを記録）。
- `save()` は保存前に自分が使えるタブか確認し、違えば保存せず「このタブは古くなっています」を最前面に表示する
- 他のタブが開いたとき（`storage` イベント）、タブが前面に戻ったとき（`visibilitychange` / `pageshow`）にも確認する。起動処理で使用権を取るまでは判定しない（新しいタブを誤って古いタブ扱いしないため）
- 同時に2つのタブで操作したときの「確認→保存」の間の競合は防いでいない（iPhone では前面のタブは1つだけなので起きない前提）
- 案内の「このタブで続ける（再読み込み）」で再読込すると、そのタブが保存済みデータを読み直して使えるタブになる

### まとめて加算パネル
- 項目（縦画面は4列×2行、横画面は横1行）: G数 / BIG / REG / ベル / スイカ(前) / スイカR(ニューキングのみ) / レトロ達 / レトロ発
- 項目を選んでテンキーで数を入力 →「加算」。続けて別項目にも加算可
- 縦横とも項目が上、テンキーが下。テンキーは残りの幅・高さいっぱいに広げる
  - 縦画面: 入力した数値はテンキーの上。テンキーは幅最大290px・高さ最大330px
  - 横画面: 入力した数値はテンキーの右（キー左・表示右）にして、テンキーを縦に大きくする。全体の幅は最大640px
- 市販カウンターやiOSショートカットで数えた値をまとめて入れる用途（ベルはショートカットの「ベル送信」でも入れられる）

### ダミー表示
内部値は一切変えず、表示だけ置き換える。タップ操作も有効（内部値は増減する）。
ON/OFF は設定「数値表示」（デフォルト / ダミー）で選ぶ。変えるとすぐ切り替わり、起動時（再読込時）もその設定で表示する（切り替えるたびにダミー値が変わる。ON 中に機種名を半透明にするのは 2026-10 にやめた）。機種名長押しでの切替は 2026-09 に廃止（長押しはまとめて加算）。
一番下の数字は本当の数と一緒に動く（タップで +1、長押しで −1。9 の次は 0 で、下から2桁目は変えない。2026-10-04）。真ん中だけが変わると、見ている人にどこが本当の数か分かってしまうため。

| 対象 | ルール | 例 |
|---|---|---|
| ゲーム数 / BIG / REG | 変化なし | 3000 → 3000 |
| 小役・欠損（ベル / スイカ系 / 詳細記録の小役・欠損・取得） | 前後に2桁ずつ付加（1桁なら5桁。本当の数の桁が増えると1桁ずつ増える。先頭は0にしない）。2026-10 に「値の桁数に関係なく5桁」にしたが、2026-10-04 に元の足し方へ戻した | 7 → 68**7**27、31 → 68**31**27、400 → 68**400**27 |
| レトロ系 | 小役と同じく前後に2桁ずつ付加 | 3 → 68**3**27 |
| ランプ類（白(不明)を含む） | 前後に1桁ずつ付加 | 5 → 4**5**1 |

### 画面遷移
```
メイン画面 ─🔍→ 大当たり分布 ─タイトル「大当たり分布 📊」をタップ→ 設定推測 ─📋→ 実戦履歴
```
✕ は1つ前の画面に戻る（設定推測の ✕ → 大当たり分布、大当たり分布の ✕ → メイン画面）。z-index はすべて 1100 で、DOM の並び（大当たり分布 → 設定推測 → 実戦履歴）で重なり順を決めている。

### 設定推測モーダル
- 大当たり分布のタイトルをタップして開く。ヘッダー左 📋 → 実戦履歴、中央「設定推測」は押しても何もしない
- ＜推測設定＞ 設定別の確率バー
- ＜実践値＞ 総回転数 / 現在獲得枚数（欠損があれば横に赤字で「(-○枚)」）/ 高設定期待度 / 期待機械割 / 期待獲得枚数
- ＜詳細データ＞ 各要素の実測値。行タップで個別設定推測グラフ、ランプ行は長押しで色別行を展開
  - 推測に使う行は項目名の左端に青い線（2026-10-04。ユーザーが3案から選択）: BIG・REG・合算・ベル・BIG(前半)スイカ／BIGスイカ・REGスイカ（ニューキング）・サイドランプ・BIG筐体ランプ・REG筐体ランプ・レトロ（色別の行も）。要素調整が 0% の要素は推測に効かないので線を出さない

    - それ以外の小役: 通常時：リプレイ（3）・ベル（3）・チェリー（3）・スイカ（3） / 通常時：リプレイ（1・2）・ベル（1・2）・チェリー（1・2）・スイカ（1・2） / BIG：チェリー・スイカ・純ハズレ / REG：純ハズレ

#### 設定推測の計算（`calc()`）
各要素の二項・多項尤度に要素調整の重み（`w/100` 乗）を掛けて積を取る。

```
totalL = BIG × REG × 合算 × ベル × BIGスイカ × REGスイカ × レトロ
       × BIG筐体ランプ × サイドランプ × REG筐体ランプ(下限示唆) × 朝一ランプ
```
BIG・REG・合算は情報が重複するが、ユーザーは重複前提で重みを調整しているので3つとも掛ける。

期待機械割は1位の1/10未満の設定を除外して正規化した確率で payout を加重平均する。
期待獲得枚数 = 総回転数（通常時＋ボーナス。`通常時G + BIG × bigG + REG × regG`、詳細記録の +1・1枚掛けの補正込み）× 0.03 ×（期待機械割 − 100）。機械割はボーナス中も含めた投入に対する割合なので、以前の「通常時Gだけに掛ける」式は誤りだった（2026-09 修正）。ボーナス中の掛け枚数の違いは考えない。

#### 詳細記録を使った計算（`coinStats()`、2026-09-30 段階4。式と理由は docs/DETAIL_MODE_PLAN.md「計算」）
- **現在獲得枚数**: 通常時リプレイが1以上なら詳細の式（払い出しの合計 − 3 × 通常時G。ベル0の理論値補完はしない）、0 なら今までの式（`calcDiffReal`）。欠損枚数はどちらでも横に出す（差し引きはしない）
- **回転数の +1**: ボーナス中の欠損・純ハズレ（ニューキングは BT中のベル・リプレイも）は1回ごとにボーナスの G数 +1。その区間のスイカの分母にも足す（ニューキングの BIG(前半)スイカは前半の欠損だけ）
- **1枚掛け**（ニューキング以外）: 1枚掛けのゲーム数 = ボーナス揃えミス + 1枚掛けで取れた小役。設定「1枚掛けの計算」が予測値なら分母の通常時G に +2/3、実測値なら +1 して −1枚。BIG・REG・合算・ベルの分母と総回転数に使う
- 詳細を記録していなければ、どの値も今までと同じ

### 大当たり分布モーダル（🔍）
（旧名「大当たり分析」。以前は設定推測から開いていたが、メイン画面から最初に開く画面に変更）
タブ2つ。
- タブの下に **全体 / BIG / REG** のボタン。当選履歴と確率表で共通（選択も共通）
- BIG の色（テンキーパネルの「BIG」ラベル、当選履歴の「BIG」バッジ）は赤系、REG は青。白で表示している所は白のまま
- **当選履歴**（2026-10-04 に見直し）: 左に円グラフ、右に統計（回数・平均・最大・最小を2×2。未入力は除外）、その下に割合、一覧（上が新しい）。G数（または棒）のタップで修正（G数と契機・告知）
  - 一覧の先頭の行は今のハマり（前回の当たりから回した分。当選の行と同じメモリ。修正はできない）。上部の緑の「前回の当たりから」の枠は廃止。記録が無くてもこの行は出す
  - 初期値以外の契機・告知（備考）は棒の下の決まった高さの段に1行で出す（長いときは …。フリーズは橙）。備考が無い行も同じ段を持つので、備考の有無で行の高さは変わらない
  - 円グラフ（ユーザーが3案から案C を選択）: 全体＝BIG/REG の回数の割合、BIG・REG＝先告知（単独(先)）・後告知（単独(後)）・小役重複（チェリー・スイカ・リプレイ・ベル）の割合。プレミアは外側の金の線の長さ（その種別の当選に対する割合）。真ん中は種別と回数。円の下に割合（四捨五入）: 全体は BIG・REG・後告知・小役重複・プレミア、BIG/REG は先告知・後告知・小役重複・プレミア
  - プレミア＝告知がプレミア点滅・フリーズ、または備考に特殊テンパイ音・バイブ・バウンドストップ（古い記録のアメイジングチャンスも）が付いた当選（ユーザー指定）。契機の無い古い記録は初期値（単独(先)＝先告知）として数える
  - 平均（大当たり確率）は `1/((記録の合計 + 今のハマり) ÷ 回数)`。今のハマりは選んだ種別から数えた分（BIG タブなら最新 BIG から）
  - 一覧の各行にデータカウンター風のメモリ。**100G の箱が10個**（箱の間は広めに空けて100G ごとを分かりやすく）、**各箱は10分割で 10G 単位**に点く（1〜10G で1目盛り、235G なら2箱と4目盛り）。10G ごとの区切りは細い線。1000G を超えた記録は全部点けて「↑」。未入力・未入力を含む区間（BIG/REG 表示の「*」付き）・0G は点かない
  - メモリを広く取るため、行の番号・G数・種別の欄は詰めてある（375px 幅でメモリ約200px、10G の目盛りは約1.8px）
  - 点いたメモリの色は位置ごとに 少ない→多い で **青→緑→黄→赤**（10段階のざっくりしたグラデーション）。BIG/REG では色を変えない（種別は右のラベルで分かる）
- **確率表**: 種別ボタンの下に設定タブ（初期値=推測1位、手動切替）。全体=合算確率、BIG=BIG確率、REG=REG確率で「その回転数までに当たる確率」と実績（その種別の当選間隔のうち、その回転数以内だった割合。未入力を含む区間は除外）を並べる。実績が理論以上なら緑、未満なら赤
  - 行: 100G / 確率分母G / 80%到達G / 分母×2〜N倍（上限未満）/ 90%到達G / 1000G を確率昇順
  - 上限は 全体=1000G、**BIG・REG=2000G**（分母が大きいため。BIG・REG は 1000G の行も残し、最後に 2000G の行）
  - G数は切り上げ、確率は小数1位で切り捨て（四捨五入しない）

  - 信頼度: 最低 / 低 / 中 / 高 / 最高 / 虹。**押したランクだけ**を表示（「最低以上」ではない）。複数選択、初期値は全部 ON
  - 高設定期待度: 0～10 / 11～30 / 31～50 / 51～80 / 81～99 / 100（%）。複数選択、初期値は全部 ON。％は**小数を切り捨てて**判定する（10.9% は 0～10、99.99% は 81～99）。「100」は**高設定以外の確率が完全に0の日**（確定示唆など）だけ

#### 信頼度
```
LLR = log(1位の尤度) − log(2位の尤度)
信頼度 = 1 − exp(−LLR / 2)
```
| ランク | 条件 |
|---|---|
| 最低 | < 5% |
| 低 | 5〜20% |
| 中 | 20〜40% |
| 高 | 40〜75% |
| 最高 | 75%以上（確定示唆なし） |
| 虹 | 最高設定の確定示唆あり（ニューキング=REG筐体紫、他=REG筐体虹）。信頼度の数値に関係なく |
