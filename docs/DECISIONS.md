# 設計判断ログ

経緯を知らずに「改善」すると過去の議論をやり直すことになるので、判断と理由、却下した案を残す。**却下案はユーザーが明示的に求めない限り再提案しない。**

## 計算・データ

### 朝一BIGランプは色カウントに含めない
ユーザー仕様。朝一の色は `morning` にだけ記録し、下線表示のみ。推測では BIG 回数を1回分減らす（白の誤計上防止）。一度「色カウントも減らす」修正を入れたが仕様誤解だったので差し戻した。

### BIG筐体ランプ `lampB` は直接確率として扱う
5色の合計が `1/blamp` と一致することを数値で確認。以前の逐次抽選変換は誤りだった。

### 合算(gas)の尤度も総合推測に掛ける
BIG・REG と情報が重複するのは承知の上。ユーザーが重複前提で重みを調整しているため。

### ニューキングⅤ 設定Vのサイドランプ
既存ツールとの乖離調査の結果、「完全均等（旧設定6型）」ではなく寒色寄りの振り分けを採用。合計が101%になっていたため、黄と赤を0.5%ずつ減らして 26.5 / 19.5 / 28.5 / 25.1 / 0.4 に確定。

### スプレッドシートは生データのみ保存、推測は読み込み時に計算
要素調整を変えたら過去データにも反映させたい、というユーザー要望。保存時に推測結果や復元用JSONは書かない（末尾4列は空欄）。

### シート保存は常に個人の値、朝一ランプは保存しない（2026-09 Codexレビュー後）
「全て」表示で保存すると G/BIG/REG が台の累計、ベル・スイカが個人分と混在し、履歴の再計算で推測が変わっていた。打ち始め列を追加する案もあったが、ユーザー判断で「常に個人の値で保存」に統一。朝一ランプの列追加も不要（保存しない）。

### 未入力のまま閉じた当選記録は現状維持（2026-09）
BIG/REG を押してG数を入れずに閉じると、それまでのハマり分が `cur.g` から消える（`hitTailG=0` かつ `g:null` は0扱いのため）。あとで入力すれば戻るので、ユーザー判断で**現状のまま**。当選履歴の統計「回数」も未入力を含む全件のまま。

### レトロ条件達成の自動加算（2026-09）
ユーザー仕様: 100G以内の連チャン中、BIG が2〜4個目の間の当たり（BIG・REG）で +1。後告知・フリーズ・目押しミスがあるので手動の補正は残す。実装は「hits から数えた値の前回との差分だけ retro_d に足す」方式（手動補正と両立し、G数の修正・取り消しにも追従できる）。設定の ON/OFF は付けない（常に自動）。まとめて加算・入力モードでは増やさない。

### 信頼度の境界・高設定期待度の帯の改定（2026-09）
信頼度の計算式（1位と2位の対数尤度比）は変えず、境界だけ 10/25/50/80 → 5/20/40/75 に。高設定期待度の帯は 5/30/60/90 → 10/30/50/80 に（0～10 / 11～30 / 31～50 / 51～80 / 81～99 / 100）。どちらもユーザー指定。サンプル39日の分布を見て決めた（SPEC.md「信頼度」）。

### 信頼度ランクの虹は確定示唆のみ
「どれだけ尤度が高くても確定示唆がなければ最高止まり」。

### 大当たり履歴の管理方式
- BIG/REG を押した瞬間に記録を作る（押したのに記録されないのはおかしい、という指摘）
- `cur.g` は「打ち始め＋記録合計＋ハマり」。記録合計で上書きする方式は現在ハマりが消えるので不可
- `_lastHitTotal`（前回合計との差分）方式は新規当選時に二重加算するので廃止し、編集セッション単位で `hitTailG` を固定する方式にした
- 削除時の区間は新しい側へ繰り入れる（古い側は誤り。一度間違えた）
- 最新の当選を消したときは「押す前のハマり（`pre`）」に戻す（2026-09 ユーザー要望）。以前は削除した区間Gをそのままハマりに残していたが、「BIG/REG を減らしても加算されたG数が戻らないのが気になる」とのこと。当選Gごと差し引く案は、押す前のハマりまで消えるので不採用

### 差枚係数
ドラゴン・キングは実測で調整（docs/CALIBRATION.md）。ニューキングⅤは構造的に合わないので放置。

## UI

- 画面遷移は「メイン→🔍→大当たり分布→(タイトルをタップ)→設定推測」（2026-09 に「メイン→設定推測→大当たり分析」から変更。名称も「大当たり分布」に）
- 機種名は タップ＝まとめて加算 / 長押し＝ダミー表示（2026-09 に入れ替え）。起動時にダミー表示が解除されてしまうので、設定「起動時の数値表示」で初期状態を選べるようにした
  - 2026-09-30（詳細記録モードの段階1）にさらに変更: 長押し＝まとめて加算、タップ＝詳細記録画面との切替。ダミー表示の切替は設定「数値表示」だけにし、変えたらすぐ反映。詳しい理由は docs/DETAIL_MODE_PLAN.md
- 「個人／全て」表示は 2026-09-30 に廃止（常に個人）。持ちコイン・欠損は打ち始め前の小役が分からず個人でしか出せないため（docs/DETAIL_MODE_PLAN.md）
- 打ち始めは設定画面の入力欄をやめ、メイン画面の＜打ち始め＞を＜現在＞と同じ操作で変える（設定「打ち始めの操作」、初期値「できない」＝誤操作防止）。変えたら＜現在＞も同じだけずらす
- 2026-10: 設定「ベルのタップ」「打ち始めの操作」を**カウントロック**（項目ごとのロック、専用画面）にまとめた。ロックはタップだけでなく入力モードも止める（メイン画面では表示だけ）。まとめて加算・ショートカット送信は止めない。全機種共通
- タップ時の振動は iOS 18 のスイッチ型チェックボックスの触覚フィードバックを流用（`navigator.vibrate` は iOS Safari 非対応）。非公式な方法なので iOS 更新で効かなくなる可能性あり。全セル対象。2026-10 に設定を廃止して常に ON（ユーザー判断）
  - 最初はタップ処理中に `label.click()` をプログラムから呼ぶ方式にしたが、WebKit の修正でプログラムからの click では振動しなくなった（Codex レビューで判明）。セルに透明ラベルをかぶせて**本物のタップ**で切り替える方式に変更。プログラムからの click 方式に戻さないこと
- 実戦履歴の信頼度フィルタは「最低↑」のような以上指定をやめ、押したランクだけ表示する複数選択に（初期値は全部 ON）。「信頼度は低いが高設定は確実」な日は高設定期待度フィルタ（帯は当初 0～5/6～30/31～60/61～90/91～99/100。2026-09 の改定で 0～10/11～30/31～50/51～80/81～99/100 に。小数は切り捨て）で拾う。信頼度の計算式は変えない（ユーザー判断）
- 大当たり回転数の入力は4桁まで（9999G）
- BIG/REG 減算時の削除確認UIは廃止（即削除）。修正は当選履歴から行う
- 緑の「取込」通知バナーは邪魔なので廃止済み（受信箱機能自体も削除）
- ボタンが大きすぎる／ヘッダーが高すぎる、という指摘が繰り返しあった。サイズを決めるときは `.hist-filter-btn` とメイン画面ヘッダー(40px)に合わせる

## 却下・撤去した案（再提案しない）

| 案 | 結果 | 理由 |
|---|---|---|
| GAS 受信箱による背面タップ連携 | 実装後に**全撤去** | 実戦でベルが約80回欠落（1/7.5→1/8.5）。通信不確実性。コードもGAS側APIも削除済み |
| ショートカットで localStorage / ファイルを直接書く | 不可 | iOS Safari の JS はファイルアプリや他アプリ領域にアクセスできない |
| ファイル選択で自動加算＋ショートカットでリセット | 見送り | 画面遷移2回で手入力より遅い |
| 背面タップのトリプルタップでリセット | 不採用 | 誤タップする。リセットはコントロールセンターに置いた |
| Web Bluetooth で物理ボタン連携 | 不可 | iOS Safari 非対応 |
| BLE キーボード化した ESP32 物理ボタン | 保留 | 唯一「他アプリ中も確実に自動反映」できる案。内部カウント保持＋F13〜F24キーで送信する設計まで検討済み |
| ネイティブアプリ化 | 不採用 | 開発者登録費・審査に見合わない |

### ショートカットのベルは URL で「上書き」送信（2026-09）
`index.html?bell=N&t=送信日時` で開くと、ベルを N で上書きする。加算方式（送った分を足して count.txt をリセット）も検討したが、二重送信・送り忘れ・通信失敗がそのままずれになる（GAS 受信箱でベル約80回欠落と同じ種類のリスク）ため不採用。上書きなら何回送っても次の送信で正しい値に戻る。アプリ内のベルのタップは残す（次の送信で上書きされる前提、ユーザー判断）。まとめて加算も残す。
送信のたびに Safari で新しいタブが開くので、古いタブが古いデータで上書きしないよう「最後に開いたタブだけ保存できる」ようにした。

## 現在の運用

他アプリを見ながらのカウントは、iOS ショートカット（AssistiveTouch で `Shortcuts/count.txt` を+1、コントロールセンターからリセット）で数え、コントロールセンターの「ベル送信」でカウンターへ上書き送信する（手入力するなら機種名長押しの「まとめて加算」）。手順は docs/SHORTCUTS.md。
