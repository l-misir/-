# データモデル

## 1. localStorage（キー: `hana_v20_data`）

キー名を変えると既存ユーザーのデータが見えなくなるので**変更禁止**。

別キー `hana_active_tab` には「使えるタブ」のID（最後に読み込んだタブ）を入れる。古いタブはこれを見て保存を止める（複数タブ対策、SPEC.md 参照）。


### 詳細小役記録 `detail`（2026-09-30 段階2。docs/DETAIL_MODE_PLAN.md「持ち方」）
- 今の項目（`cur.bell` `cur.suika` `cur.suikaR` `lamps` の各色）を**合計として正**にし、詳細にしか無い値だけを `detail` に持つ。詳細記録 OFF の間も持ち、今の計算には使わない（計算は段階4）
- 項目は `DETAIL_ITEMS`（ニューキング / それ以外）。全機種が全項目を 0 で持つ（形を揃えるため。その機種で使わない項目は 0 のまま）
- 1回の成立は1つの欄にだけ数える。例: 通常時チェリー = `nChe`（4枚）/ `nCheM`（中段・2枚）/ `lnChe`（欠損・0枚）の合計
- `of` の付いた欠損は今の合計に含まれる（取得 = 合計 − 欠損）: ニューキング `lbSui`⊆`cur.suika`（BIG前半スイカ）・`lrSui`⊆`cur.suikaR`、それ以外 `lbSui`⊆`cur.suika`（BIGスイカ）。欠損は合計を超えない（`save()` の `clampDetailLoss`。今の画面で合計を減らしたら欠損も一緒に減る）
- 読み込み時に足りない項目は 0、0 以上の整数にそろえる（`normalizeDetail`）。リセット・シートからの復元は 0（シートの詳細列は段階4）

| `oRep` `oBell` `oChe` `oSui` | – | 1枚掛け リプレイ・ベル・チェリー・スイカ |
| `bChe` | BIG(前半)チェリー | BIGチェリー |

`loadData()` は欠けたキーを `DEFAULTS` / `SINGLE_DEFAULT` で補完する（機種データ内の `start` `cur` `lamps` `morning` も、既存値を保持したまま補完）。構造を足すときは `SINGLE_DEFAULT` に足せば補完されるが、`cur` `start` `lamps` 以外の階層を足すときは `loadData()` にも補完処理を追加すること（古い保存データでクラッシュさせない）。

実戦履歴の再計算（`calculateAllHistoryRows`）は、行ごとに `data` を一時的な別オブジェクトへ差し替えて `calc()` し、同期区間の中で必ず元に戻す。操作中の `data` 自体を書き換えると、途中の `await` 中のタップで過去データが localStorage に保存される。

### 朝一ランプ
朝一のBIGランプは**色カウンターには入れない**。`morning` にだけ記録し、詳細データの該当色に下線を引く。推測では BIG回数を1回分減らして白の誤計上を防ぎ、偶奇示唆は `mornRate` で別途反映する。

## 2. 大当たり履歴 `hits`

### 意味
データカウンターは BIG/REG どちらでも当選で回転数が0に戻る。`g` はその表示値＝「直前の当たりからの通常時回転数」。

```
時系列:  [着席] --300G--> BIG --300G--> REG --100G--> REG ... --230G--> BIG --170G--> (現在)
hits:    [ {230,b}, ..., {100,r}, {300,r}, {300,b} ]   ← 先頭が最新
hitTailG = 170（最新の当たり以降のハマり）
cur.g    = start.g + Σg + hitTailG
```

### 種別フィルタ
BIG タブなら BIG 間、REG タブなら REG 間の実間隔を出す。古い順に走査し、対象種別が来るまで区間を積算する。

```
入力（新→古）: 230B 100R 80R 10R 220R 35R 95R 100R 300R 300B
BIG → [1170, 300]         1170 = 300R以降の全区間 + 230
REG → [100,80,10,220,35,95,100,600]   600 = 300R + 手前の300B区間
```

「現在ハマり」表示: 全体=hitTailG、BIG/REG=hitTailG＋最新から対象種別までの異種区間。

### 操作と整合性
| 操作 | 処理 |
|---|---|
| BIG/REG を +1 | 記録 `{g:null, pre}` を先頭に作成（`pre` = 押す前のハマり = `(cur.g − start.g) − Σg`。G数を記録の合計より小さく手入力していた場合はマイナス）→ `hitTailG=0` にして**開いた時点で `cur.g` を記録に合わせて保存**（未入力のまま再読込しても、削除時に `pre` を二重に足さないため）→ テンキーでG入力（入力のたび即反映、閉じても残る） |
| BIG/REG を -1 | 実際に値が減った時だけ `removeLatestHit(kind)`。削除直前に `hitTailG = (cur.g − start.g) − Σg`（＝押した後に回した分）で取り直す。**最新を消したら `hitTailG += pre`**（押す前のハマりに戻す。`pre` の無い旧データは区間Gを足す）。最新以外なら区間Gを idx-1 へ繰り入れ、idx-1 の `pre` も区間G分伸ばす（押す前のハマりの起点が消えた当たりだったため）。`hitTailG` は保存されないので、取り直さないと再読込後やG数タップ後にハマりが消える |
| 履歴のG数をタップ | `editHitG(idx)`。ハマりを固定し、最初の数字入力で既存値を上書き |
| 入力モード / まとめて加算で BIG を増やす | `hits` は変化しない（仕様） |

確率表の実績は `g != null` の記録だけで集計する（`null <= 100` が true になる JS の罠に注意）。

`hitTailG`（編集・削除のときに `(cur.g − start.g) − Σg` で取り直す）と `pre` は、G数を記録の合計より小さく手入力した状態ではマイナスになるが**丸めない**（途中で0に丸めると、無関係な編集や削除で G数が増える）。下限は `cur.g ≥ start.g`（`syncGameCountFromHits`）と、ハマりの表示（`currentHamari` は0未満を0に）だけにかける。

## 3. スプレッドシート

機種ごとに1シート。1行目は空、2行目が見出し、3行目からデータ。**生データのみ**（推測設定・期待度・差枚は読み込み時に再計算）。

**列の定義は `sheetColumns(m)`（index.html）の1か所**で、保存（`sheetRowData()`。TSVコピーとシート保存で共通）・読み込み（`machineDataFromRow()`）・新しく作るシートの見出しをすべてそこから作る。並びは 2026-10 にユーザーが指定（ニューキングは指定どおり、ほかの4機種はそれを元に確認した案）。

- G/BIG/REG は常に**個人（打ち始めからの差分）**。打ち始め値・朝一ランプは保存しない（復元は `start=0`、`morning=-1`）
- 総回転数・BIG：回転数・REG：回転数は設定推測と同じ計算（`coinStats`。詳細記録の +1・1枚掛けの補正込み、総回転数は四捨五入）
- 「(欠損)」と対になる列（例: BIG前半：スイカ）は**取得した回数**（ボタンで押した回数）。成立回数 = 取得 + 欠損。読み込みでは「今の合計 = 取得 + 欠損」で戻す
- 詳細記録の列は**詳細を記録していない日は空欄**（＝記録なし。0 は「記録して0回」）。今の項目（ベル・スイカ・ランプ・レトロ）は毎日入る
- 当選履歴は古い順に「B120 R45[チェリー] B30[フリーズ・バイブ] R-」（`hitsToText` / `textToHits`）。B/R と回転数（未入力は -）、契機・告知・付随は初期値以外だけ［］に「・」区切り。復元で戻す（`pre` は保存しないので、復元後に最新の当選を消したときは区間の G 数をハマりに戻す従来の扱い）。レトロ達成はシートの値のまま（`retroAuto` を当選履歴から数えた数にして二重に足さない）
- 1枚掛けの計算（ニューキング以外）: `予測値` / `実測値`。履歴の再計算・復元でその日の値を使う（復元では設定も切り替える）。値の無い行は、再計算は予測値で行い、復元では設定を変えない
- 見出しの「黃」は「黄」に統一
- **A 列は1行メモ**（2026-10-08 ユーザー要望）。アプリは空欄で保存し、メモはシートで書く（アプリでは読まない・出さない）。下の列の番号は B 列からの順

### 読み込みの条件
- GAS（`gas/Code.gs`）は「2列目が空でなく、3列目が数値」の行だけを返す（見出し行・空の行は飛ばす）。メモ列あり（2列目＝日付・3列目＝総回転数）もメモ列なし（2列目＝総回転数・3列目＝通常時）もこの条件で読めるので、GAS の変更・再デプロイは不要
- **メモ列の無い行（2026-10-08 より前の並び。A 列が日付）も読める**（`rowHasMemo` / `rowColumns`）。B 列が日付ならメモ列あり、そうでなければメモ列なし
- **整理前（2026-10 より前）の並びは読まない**（2026-10-08 ユーザー判断）。A 列が空欄で B 列が日付なので、メモが空欄の行と見分けられないため。シートは下の移行で整理後の並びに置き換え済み。参考: A 空欄・B 日付・C 総回転数・D 通常時・E ボーナス回転数・F BIG・G REG・H ベル…Z レトロ発生・AA〜AD 空欄・AE 1枚掛けの計算・AF〜 詳細

### A 列（メモ）の追加（2026-10-08）
- ユーザーが各機種のシートで A 列の左に1列挿入し、見出しを「メモ」にする。**新しい版で保存する前に挿入する**（挿入前のシートに保存すると、その行だけ1列右にずれ、後から列を挿入するとさらにずれる）
- 「歴代記録」の式は機種シートの範囲（例 `'キングハナハナ'!B3:B…`）を参照しているので、列の挿入で Google スプレッドシートが自動でずらす（式の直しは不要。挿入後に合計が変わらないことを確かめる）
- 挿入前の行（A 列が日付）も読めるので、挿入とアプリの公開の順番で実戦履歴が壊れることはない

### 既存シートの移行（2026-10）
ユーザーが書き出した xlsx を、`sheetColumns` と同じ並びに変換したファイルで置き換える（変換は一度きりの作業なのでリポジトリには入れていない）。変換前後の全行をアプリの `machineDataFromRow` で読んで同じ機種データになること、新しい「歴代記録」の回数の合計が今の値と一致することを確かめた。
- 整理前の行は欠損を記録していないので、今までのスイカの回数をそのまま「取得」の列へ。BIG：回転数・REG：回転数は BIG × bigG・REG × regG
- 「歴代記録」は新しい列に合わせて作り直す。**5機種を1つの表**にし、見出しはユーザー指定の並び・名前で共通化（ニューキングの BIG前半チェリー・スイカは「BIG：チェリー」「BIG：スイカ」、BIG後半サイドは「REG：サイド」、筐体ランプの紫は「赤」の列）。その機種に無い項目は「／」。書式はユーザーの機種シートに合わせて統一（見出しは Arial 太字・#EFEFEF・中央・折り返し・細い罫線、データは Arial・中央・細い罫線、列幅は機種名 25・ほか 14）。各項目の「回数」（小役は成立回数 = 取得 + 欠損）と「確率」、欠損は回数だけ。詳細記録の項目は**記録した日だけ**の回転数を分母にする（`SUMIFS(…, 項目の列, "<>")`）。ニューキングの BIG前半は「14 × BIG + 前半の欠損」、BT は「BT中リプレイ + BT中ベル + BIG」、REG は「10 × REG + REG の欠損」。想定総差枚数は今の式（係数も今のシートのまま）
- 移行と新しい版のアプリの公開は同時に行う（新しい版は新しい並びで保存するので、整理前のシートに保存すると列がずれる）

## 4. GAS Web App API（`gas/Code.gs`）

全リクエストに `token` が必要（不一致は `{"error":"unauthorized"}`）。

| メソッド | パラメータ | 動作 |
|---|---|---|
| GET | `action=getAll&token=` | `KNOWN_SHEETS` の全行を `{sheet,row,values[]}` で返す。Date は `yyyy/MM/dd HH:mm` |
| GET | `action=delete&sheet=&row=&token=` | 指定行を削除 |
| POST | body `{token, sheetName, headers, rowData}` | シートが無ければ headers 付きで作成し、rowData を追記 |

POST は CORS プリフライト回避のため `Content-Type: text/plain;charset=utf-8` で送る。
