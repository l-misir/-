# iOS ショートカット: ベルのカウントと送信

他アプリを見ていても AssistiveTouch からショートカットでベルを数えられる。数えた値は ③「ベル送信」でカウンターへ送る（カウンターのベルを **送った値で上書き**）。送信を使わず、カウンターの「まとめて加算」（機種名タップ）で手入力することもできる。

動作確認環境: iPhone SE（第3世代）/ iOS 18.7.8。カウンターは **Safari で開く**（ホーム画面に追加したアイコンからだと保存領域が別になり、送信が届かない）。

## 前提
「ファイル」アプリ →「このiPhone内」→ 右上「⋯」→「新規フォルダ」で **`Shortcuts`** フォルダを作っておく（無いと保存も読み込みも失敗する）。

## ① ベルカウント（AssistiveTouch）

```
count.txt のパスにある Shortcuts からファイルを取得
    見つからない場合はエラー: オフ
「ファイル」からテキストを取得
「テキスト」+ 1 を計算                 ← 「計算式」ではなく「計算」アクション
「計算結果」を Shortcuts に保存        ← パス count.txt / 上書き: オン
通知「計算結果」を表示
```

ハマりどころ:
- 「計算式」アクション（f(x)）はテキストの改行等で計算エラーになる。電卓アイコンの「計算」を使う
- 初回は `count.txt` が無いので、先にリセットを1回実行する

割り当て: 設定 → アクセシビリティ → タッチ → AssistiveTouch → カスタムアクション（シングルタップ等）に「ベルカウント」。
（背面タップに割り当てる場合: 設定 → アクセシビリティ → タッチ → 背面タップ → ダブルタップ。約2秒のクールダウンがある）

## ② リセット（コントロールセンター）

```
テキスト: 0
「テキスト」を Shortcuts/count.txt に保存（上書き: オン）
通知「🔄 リセット」を表示
```

コントロールセンター → 編集 → コントロールを追加 →「ショートカット」→ リセットを選択。

## ③ ベル送信（コントロールセンター）

`count.txt` の値（その台で数えたベルの合計）をカウンターへ送り、カウンターのベルを**その値で上書き**する。何回送っても「今の合計」で上書きするだけなので、送りすぎ・送り忘れがあっても次の送信で正しい値に戻る。

```
count.txt のパスにある Shortcuts からファイルを取得
    見つからない場合はエラー: オン          ← ベルカウントと違い「オン」。無いまま 0 を送ってベルを消さないため
「ファイル」からテキストを取得
「テキスト」+ 0 を計算                          ← 数値にして改行などを取り除く（「計算」アクション）
「現在の日付」を書式設定                         ← 入力は「現在の日付」（計算結果ではない）
                                                   日付の書式: カスタム / 書式文字列: yyyyMMddHHmmss
テキスト: （カウンターのURL）?bell=［計算結果］&t=［書式設定された日付］
「テキスト」の URL を開く
```

- `［計算結果］` と `［書式設定された日付］` は**文字で打たず**、テキスト入力中にキーボード上の変数バーから、それぞれのアクションの出力（マジック変数）を挿入する
- 書式文字列は大文字・小文字をこのとおりに（`HH` は24時間表記。`hh` にすると午後の送信が午前より古い扱いになる）
- （カウンターのURL）は、Safari で開いているカウンターのアドレスをそのままコピーして貼る。末尾に `?…` が付いていたら消す。例: `https://xxxx.github.io/hanahana/index.html?bell=［計算結果］&t=［書式設定された日付］`
- `t`（送信日時）は、古い送信の URL をあとで開いてしまったときに上書きし直さないための印。前回以前の日時の送信は無視される（形式が違う `t` は日時なしとして上書きする）
- **送信しても `count.txt` はリセットしない**（送るのは「今の合計」）

割り当て: コントロールセンター → 編集 → コントロールを追加 →「ショートカット」→ ベル送信を選択（AssistiveTouch など他の場所から呼んでもカウンター側の動きは同じ）。

### カウンター側の動き
- Safari に切り替わり、「ベルを 120 → 135 に上書きしますか？」と確認が出る。OK でベルが送った値になり、ベルのセルが一瞬光る（キャンセルなら何もしない。今と同じ値なら確認なし）
- 送信の URL はすぐアドレスから消える（あとで再読込しても上書きし直さない）
- 上書きするのは、そのとき選択中の機種のベルだけ
- 送信で Safari に**新しいタブ**が開くことがある（既存のタブで開くかどうかは iOS 次第）。新しいタブが開いた場合、古いタブには「このタブは古くなっています」と出て保存も止まるので、閉じてよい（放置しても新しいタブのデータを上書きしない）
- `bell` が0以上の整数でない送信（`135abc` など）は無視される

## 運用の注意
- **台移動・打ち始め・カウンターのリセットのときは、② で `count.txt` もリセット**する。忘れると次の送信で前の台のベル数に上書きされる
- カウンターでベルをタップしてもよいが、次の送信で `count.txt` の値に上書きされる
- 送信にはページの読み込み（通信）が必要。電波が弱いと失敗することがあるが、あとで送り直せば正しい値になる

## 制約（iOS 仕様で改善不可）
- 同じアプリからの連続通知はまとめられ、すぐ表示されないことがある（内部的には加算されている）
- 画面消灯中は反応しない
- 通知の代わりに「バイブレーション」アクションにすると即座に手応えが返る
- 他のアプリを見たまま、裏でカウンターの数値だけを増やすことはできない（送信は必ず Safari に切り替わる）
